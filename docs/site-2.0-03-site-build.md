# 指示書 3：サイトの組み立て（サイトのリポジトリ、クラウドのセッション）

釣果ログのサイト（このリポジトリ、https://chokalog.margheritaworks.com/）を、iPhone 版 2.0 の内容に合わせて更新してください。

## 0. 進め方の決まり

### 0.1 ブランチ
1. main から `site-2.0` ブランチを作り、すべての作業をこのブランチで行ってください。
2. **main へのマージはしないでください。** iPhone 版 2.0 が App Store で公開されたタイミングで、こちらからマージを指示します。
3. 意味のまとまりごとにコミットし、`site-2.0` にプッシュしてください。
4. ホスティングがブランチごとのプレビューを作る場合は、そのプレビューの住所を報告してください。

### 0.2 素材
1. 素材は次の 2 つのリポジトリにあります。セッションに追加されていなければ追加し、読むだけにしてください。
   - iPhone 版のリポジトリ（isitest1/FishingLog）の release/2.0 ブランチ、`docs/site-2.0-assets/`（画面の写真、航跡のデータ、1.x と 2.0 の比べの画像、`features-2.0.md`）
   - isitest1/mw-bathymetry の main、`site-assets/`（航跡の動き用の地図のタイル、陸の形、埋め込みの静止画）
2. 使う素材は、このリポジトリの `assets/` の下に写してください。サイトから他のリポジトリを直接読まないでください。
3. 航跡の JSON（`track-day.json` は約 3MB）は、そのまま写さないでください。サイト用に、5 秒ごとに間引いた点だけを使い、緯度経度を小数 5 桁に丸め、動きに要る項目（時刻・緯度・経度・移動中か釣り中か・釣果）だけにした軽い形（1 ファイル 200KB 以下を目安）に変換して置いてください。変換の手順は `assets/` の中の README に書いてください。

### 0.3 書き方の決まり
1. 機能の説明は、`features-2.0.md` の事実だけをもとに書いてください。書かれていないことを足さないでください。事実が分からない所は、推測で書かずに報告で知らせてください。
2. 文章は、整いすぎた説明口調や中黒の羅列を避け、今のサイトの文体に合わせてください。
3. GPX のことは、どこにも書かないでください。
4. 底質は「泥・岩・砂など」と書き、S・M・R のような記号では書かないでください。
5. 地図データの容量（全国の MB 数など）は書かないでください。
6. 「有料の海図アプリに劣らない」のような、他のアプリと比べる書き方はしないでください。

- 「今後の予定」の節の 2 つの方針、アンケート 2 問、ご意見・ご要望のフォーム
- Android 版への案内（場所は 1 のとおり移す）

## 3. 地図の節（新規）

1. 見出し：**無料で、ここまで見える。**
2. 本文：全国の等深線と水深の色分けを、拡大するほど細かく描きます。200〜400m の深場の斜面も 10m ごと。根や駆け上がり、水深帯の広がりが、地図を見るだけでつかめます。
3. その下に、公開した地図を埋め込んでください（`https://map.margheritaworks.com/?embed=1`）。
   - スマホの幅では横いっぱい、高さは 70vh 程度にしてください。
   - 地図の下に「アプリなら、この上に底質（泥・岩・砂など）と、航跡と、釣った魚が乗ります。」と、「全国の海底の地図を開く →」（`https://map.margheritaworks.com/`、新しいタブ）を置いてください。
4. 見比べの部品
   - 小見出し：**同じ海が、ここまで変わりました。**
   - 1.x と 2.0 の比べの画像を重ね、境目を指で左右に動かして見比べられるようにしてください。左に「1.x」、右に「2.0」の札を付けてください。
   - キーボード（矢印の鍵）でも境目を動かせるようにし、画面読み上げで「1.x と 2.0 の地図の比べ」と分かるようにしてください。
5. 立ち位置の説明
   - 小見出し：**航海には使えません。でも、釣り場を読むには、これで十分です。**
   - 本文：根や駆け上がりの位置、水深帯の広がり、底質の違い。釣り場の地形を読むために要るものは、この地図に入っています。元になっているのは 500m ごとの水深のデータなので、小さな根や漁礁の形までは出ません。航海と安全の判断は、海図と魚探で。
6. 地図の機能を短く並べてください：座標と、十字までの距離・方角／進んでいる向きの線／回したときだけ出る方位磁石／底質（泥・岩・砂など）の表示／一度見た場所は電波のない沖でも表示。
7. 重ねて比べる動き
   - 小見出し：**あの日と、この日を重ねる。**
   - 本文：過去の釣行を重ねると、どこを流して、どこで釣れたかを見比べられます。期間・魚種・エリアで絞り込んで比べられます。
   - `trips-2.json` の 2 回分の航跡を、広めの地図の上に 1 本ずつ色を変えて描き足していき、それぞれの釣果の点と名前が、釣れた時刻に現れる動きにしてください。この動きはカメラを動かさず、落ち着いた見せ方にしてください。
   - `trips-5.json` は古い素材なので使わないでください。
8. 今の「海図アプリと魚探との、併用前提です」の節は、5 の説明に置き換えて外してください。

## 4. 航跡の節（新規）

1. 見出し：**出港から帰港まで、走った線が残る。**
2. 本文：出港したら「釣行を開始」を押すだけ。画面を消しても航跡を記録し、走っている所と釣っている所を自動で分けて描きます。途中でアプリが閉じても、続きから記録します。
3. 機能を短く並べてください：航行距離・出港と帰港の時刻・流しの速さ／釣行のメモ／出港を自動で見つけて記録を始める設定（初期はオフ）。

### 4.1 航跡の動き（モーショングラフィックス）

`track-day.json` の 1 日（2026/10/3、06:12 出港〜13:30 帰港）を、地図の上で約 15 秒で再生します。地図アプリが現在地を追いかけて寄ったり引いたりするのと同じ、カメラの寄り引きで見せてください。

**動きの流れ**
1. **06:12 港に寄った状態から始める**：港と岸の形、浅場の細かい等深線が見える拡大率（z15 程度）で、船が港を出て線が引かれ始める。カメラは船を追いかける。
2. **速度が上がったら引く**：「移動中」になったら、カメラを大きく引き（z12〜13 程度）、釣り場へ向かう走りが見える広さにする。
3. **釣り場で寄る**：「釣り中」になったら、また寄る（z14〜15 程度）。流しの線がゆっくり引かれ、08:47 にマダイの点と「マダイ」の名前が現れる。
4. **次のポイントへ**：アジ・カワハギの場所へ移る間は少し引き、釣れたところでまた寄る。魚の点と名前は、釣れた時刻に現れる。
5. **帰港して全体を見せる**：13:30 に港へ戻ったら、カメラを大きく引いて、1 日の航跡と釣れた魚が全部入る広さで止める。

**描き方**
- 地図は、`site-assets/map-anim/` のタイルを Leaflet（cdnjs から読み込む）で表示し、なめらかに寄る・引く機能（flyTo）でカメラを動かしてください。
- 陸は `land.geojson` をアプリの色合いに近い単色（ベージュ系）で塗り、地名を 2〜3 か所（三浦市・城ヶ島など）だけ文字で入れてください。国土地理院などの地図は下に敷かないでください。
- 航跡の線は、アプリと同じ描き分けにしてください：移動中は細く細かい点線、釣り中は実線。下に白い縁を付けて、濃い段彩の上でも見えるようにしてください。
- 線の先に船の印（進む向きの矢印）を出してください。
- 魚の点は赤い丸に白い縁、名前は枠のない赤い文字に白い縁取り（アプリと同じ見た目）にしてください。
- 画面の隅に、時計（06:12 → 13:30）と「移動中」「釣り中」の表示を出してください。アプリの記録中の表示（橙の札）に似せてください。
- 実際の時間の進み方は一定でなくて構いません。移動中は速く、釣りの場面と魚が釣れる瞬間はゆっくり見せてください。

**表示の作法**
- ページを開いた時点では読み込まず、この節に近づいたときにタイルを読み込み始めてください。
- この節が画面に入ったときに再生を始め、画面から外れたら止めてください。
- 再生し終わったら 3 秒ほど止めて、最初から繰り返してください。
- 動きを減らす設定（prefers-reduced-motion）のときは、動かさずに最後の「1 日の全体」の絵だけを出してください。
- 地図は指で動かせないようにしてください（ページを下に送る邪魔をしないため）。

## 8. よくある質問

### 8.1 直すもの
1. **機種変更するとき、記録は移せますか？**：iCloud で自動で同期される、という記述は誤りなので外してください。写真付きのバックアップで移す説明に書き換えてください。
2. **iCloud を使っていなくても使えますか？（iPhone版）**：質問ごと外してください。
3. **海図は表示できますか？**：海しるの等深線・「20m・50m・100m の粗い間隔」の記述を、2.0 の地図の説明に書き換えてください（3 の 5 の立ち位置と同じ内容）。
4. **Android でも使えますか？／iPhone と Android の間で記録を移せますか？**：航跡と新しい地図は Android 版にまだ無いこと、航跡を含む記録の移し方の制限を、`features-2.0.md` の事実に合わせて書いてください。
5. **オフラインでも使えますか？**：航跡の記録は電波がなくても動くこと、一度見た地図の場所は沖でも表示されること、前もって地図の区画を取っておけることを足してください。

### 8.2 足すもの（この順で、新しく足す質問のいちばん上に置く）
1. **航跡はどこかに送られますか？**：送られません。端末の中だけに保存します。
2. **位置情報の許可は「常に」が必要ですか？**：「使用中のみ」で記録できます。出港の自動検知を使うときだけ「常に」が要ります。
3. **電池はどのくらい減りますか？**：画面を消して記録できること、長い釣行では予備の電池をおすすめする程度にとどめ、数字は書かないでください。
4. **記録中にアプリが閉じたらどうなりますか？**：続きから記録されます。

## 11. プライバシーポリシー（/privacy/）

`features-2.0.md` の事実（最新のもの）に合わせて、次を足してください。分からない所は推測で書かずに報告で知らせてください。
- 釣行の記録中は、画面を閉じた後も位置情報を使うこと
- 出港の自動検知を使う場合に「常に許可」を使うこと（初期はオフ）
- 航跡は端末の中だけに保存し、外に送らないこと
- 地図データを取るときに、サーバー（data.margheritaworks.com）へ送られる情報
- 海況・天気を取るときに、Cloudflare の Worker と Open-Meteo へ送られる位置の細かさ（丸めているかどうかを含め、`features-2.0.md` の最新の記述どおりに書く）
- 地名を求めるときに、位置が Apple の地名のサービスに渡ること
- 分析のために、航跡のまわりの範囲を Cloudflare の Worker に送っていること（`features-2.0.md` に無い場合は、iPhone 版のソースで確かめてください）
- 更新日を新しくしてください

今のプライバシーポリシーに、事実と合わない記述（「位置を送らない」など）があれば、事実に合わせて直し、直した所を報告してください。
