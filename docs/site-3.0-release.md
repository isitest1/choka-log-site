# サイト 3.0 の公開の段取り

iPhone 版 3.0 が App Store で承認されて公開される日に、ブランチ `site-3.0` を `main` にマージして、サイトを 3.0 にする。

- マージは、本人の指示があってから行う（作業者の判断ではマージしない）。
- 2026-11-04 の時点で、`site-3.0` は本人が確認を終えた状態（「全体的に問題ない」）。この後は、下の「公開の日に直すもの」のほかは変えない。
- 2026-11-04 の時点で、`main` との食い違い（コンフリクト）はない。`main` に別の変更が入ったときは、マージの前に `main` を `site-3.0` に取り込んで確かめる。

## 公開の日に直すもの（マージの前に `site-3.0` で直す）

| 場所 | 直すこと |
|---|---|
| `index.html` の更新履歴（`<!-- 3.0 の公開の日に… -->` の行） | 3.0 の「2026年12月」を、公開の月（または日付）にする |
| `privacy/index.html` の最終更新日（`<!-- 3.0 の公開の日に… -->`） | 「2026年11月4日」を公開日にする |

## 公開の前に本人に確かめること

- App Store のバッジの画像 `assets/img/appstore-badge-ja.svg` が、`main` にも `site-3.0` にも無い。いまは代わりのオレンジのボタン（「App Store でダウンロード」）が出ている。バッジを出すなら、Apple の公式のバッジの SVG を本人から受け取って置く。
- 今後の予定のアンケートの 3 問目（`q=chokyo-area-v1`）を、アンケートの受け口（API）が受け付けるか。
- 「データの出どころ」の今釣れのクレジットの書き方。
- 3.0 の公開のときに、釣況の対応の海域が増えていれば、「相模湾・東京湾など6つ」と FAQ の海域の一覧を直す。
- 振り返りの画面（`hero-review`・`r4-review`）に「06:49 → 10:00（3h10m）」と「釣り 8h02m」が並んでいる。og.png にも同じ画面が入っている。アプリ側で直した画面に替えるか。
- Android 版が 3.0 になったら、Android 版の節とページを直す（別の作業）。

## マージの手順（本人の指示の後）

1. `site-3.0` の上で、上の「公開の日に直すもの」を直して、コミットとプッシュをする。
2. `main` に `site-3.0` をマージして、`main` をプッシュする（GitHub Pages は `main` だけを配信する）。
3. 数分待ってから、https://chokalog.margheritaworks.com/ を開いて確かめる。
   - トップの 3 枚（左 地図・中央 釣況のいま・右 振り返り）、いまの動画が iPhone で映るか、取り込みの 1・2・3 が開くか。
   - `/privacy/`、`/analysis/`、`/android/` が開くか。
   - 古い見た目が残っていないか（`site.css?v=3.0.2` を読んでいるか）。
4. 本人に、公開したことと確かめた結果を伝える。

## 3.0 で変えたもの（覚え書き）

- トップ：3.0 の構成（いま、撮るだけ、地図、振り返り、作戦、たまるほど、プラス、取り込み）。Android 版から下は、文を縮めたほかは 2.0 のまま。
- プライバシーポリシー：AI の振り返り・釣況・海面水温・取り込みの節を足し、番号を振り直した。
- 分析のページ：3.0 での変更の注記。
- 画面と動画：`assets/img/3.0/`。デモの記録の画面には「デモ用の記録です」と添えてある。
